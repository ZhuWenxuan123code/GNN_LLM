# Evaluating LLMs on Large-Scale Graph Property Estimation via Random Walks

## 基本信息

- Paper ID：doi:10.18653/v1/2026.acl-long.1846；arXiv:2605.01484
- 作者：Sunil Kumar Maurya、Xin Liu
- 年份与发表状态：2026，ACL 2026 Long Paper，pages 39749--39777
- 论文页面：[ACL Anthology](https://aclanthology.org/2026.acl-long.1846/)，[arXiv](https://arxiv.org/abs/2605.01484)
- PDF：[ACL 官方 PDF](https://aclanthology.org/2026.acl-long.1846.pdf)
- 阅读级别：全文精读
- 对应证据线：1、2、5、6

## 一句话结论

EstGraph 证明 LLM 可以从 random-walk statistics 对百万级、部分可访问图做若干全局属性估计，但它提供的是采样访问与规模 OOD 的任务级证据，不是 Graph-LLM 内部 permutation-consistent 或 causal topology representation 的证明。

## 研究问题与真实贡献

- 作者声称解决的问题：现有 LLM 图推理 benchmark 多把完整图放入小规模 prompt，不能评估图规模达到万级、百万级且只能通过局部访问获得信息时的估计能力。
- 方法的真实新增部分：构造 EstGraph benchmark，包含 graph size（节点/边）、community count、graph structure type 和 influential-node ranking 四类估计任务；用 simple random walk 或 Metropolis--Hastings walk 的统计摘要代替完整 edge list，控制 prompt 长度。
- 与已有方法相比的关键差异：相对 NLGraph、GraphQA、GraphPattern 和 GraphArena 的 full-visibility exact QA，EstGraph 采用 partial-graph access、random-walk summary 和 global-property estimation；它是评测/数据构造增量，不是新的 Graph-LLM encoder 或 tokenizer。

## “图结构”的具体含义

- 结构粒度：局部随机游走、节点访问频率、节点度分布、碰撞/回返时间，以及由此推断的全局规模、社区、图类型和中心性。
- 图信息输入形式：walk length、unique nodes/edges、first collision、return time、每 10% walk 的累计新节点数、访问频率、节点 degree、平均 degree、部分匿名节点名和多条 walk 的合并统计。
- 信息路径：Graph → simple/MH random walk sampler → hand-crafted statistics → natural-language prompt → API LLM → numeric/class/type/ranking output。
- GNN 是否可能已经完成主要计算：没有 GNN。random-walk sampler、degree statistics、Chapman estimator 和 centrality ground truth 负责结构访问或参考计算；LLM 主要承担统计解释和估计表达，因此无法从结果定位 LLM 的独立拓扑责任。

## 方法机制

输入图为无向图 G=(V,E)。simple random walk 在当前节点的邻居中均匀采样，节点访问分布和 degree 分布作为图结构摘要。graph-size 任务使用两组独立样本的 Chapman capture-recapture estimator 估计节点数，再用估计平均 degree 推算边数；其他任务将 walk 中节点访问次数、degree 和统计量拼入 task-specific prompt。实验比较 uniform sampling、Metropolis--Hastings、max-degree walk、return-time estimation 等 classical baseline，以及 gemini-2.5-pro、sonnet-4、o3（high reasoning effort）和 DeepSeek-V3.1 Thinking Mode。size estimation 中 synthetic/real-world prompt 通常使用 20% graph-size sampling，random walk 采用 10% graph-size burn-in；community task 使用每个 community 的 2--3 个 seed、长度 300 的 walk；structure task 使用 5 条、长度约为图节点数 10% 的 walk。论文不训练 Graph-LLM，也没有 learnable graph-to-LLM connector。

## 实验设计与结果

- 数据集与任务：四类任务。1）估计节点数和边数；2）估计 LFR 图的 community 数；3）根据 degree distribution 识别 BA、ER、LFR、Grid；4）从 LFR 图的 random-walk statistics 预测 top-k（k=20、50、100）的 Betweenness、Closeness、PageRank 节点。
- 数据划分：size estimation 使用 BA、ER、GRP 三类 synthetic 图，分为 small 100--1,000、medium 1,000--10,000、large 10,000--100,000 nodes，并加入 SNAP 的 ego-Twitter、twitch-gamers、email-EuAll、as-skitter、wiki-Talk；community/ranking 使用随机生成的 1,000--5,000 node LFR 图，structure task 使用 BA、ER、LFR 和三类 lattice/grid 图。论文给出每类 EstGraph 配置 100 graphs 的数据统计，但没有将 topology family 作为明确 held-out split。
- Baseline：uniform node-list sampling、Metropolis--Hastings、max-degree walk、return-time estimation，以及 Greedy Modularity、Louvain、Label Propagation；LLM baseline 为 gemini-2.5-pro、sonnet-4、o3 和 DeepSeek-V3.1 的不同 walk prompt。
- 主要指标与结果：节点/边估计使用 relative error 的 median、mean、std；community 使用 mean absolute error；structure 使用 accuracy；ranking 使用 Precision@20/50/100。synthetic size estimation 中 LLM 在不少设置的 median relative error 低于 20%，o3 常为最佳 LLM；但 real-world 图误差更高且有显著 outlier。simple random walk 相对 MH prompt 的整体效果在论文总结中约为 BA 78%、GRP 51%、real-world 9% 的相对水平。community count 的 LLM MAE 约为 1.9--2.6（真实 community 数为 5--12），说明能识别多社区但不够精确。structure classification 对 Grid 为 100%；o3 对 BA/ER 为 93.3%/93.3%，但对 LFR 仅 26.7%。Precision@20 中 o3 的 Betweenness/Closeness/PageRank 为 31.5/35.0/81.0%，其他模型显著更弱；PageRank 比 shortest-path centrality 更容易从访问频率近似。
- 关键消融：MH 与 simple random walk、sampling coverage、burn-in、walk length、不同模型、不同 graph family、多条 walk 和 classical estimator 对照；Appendix 给出 edge estimation、Precision@50/100、walk statistic/prompt template 和 practical recommendations。但作者明确没有系统遍历 sampling size、burn-in rate、random initialization 等超参数。
- 是否足以支持作者结论：足以支持“random-walk summary + LLM 能在若干大图估计任务上产生有用但不稳定的近似”，也支持把 partial access/scale 作为补充 benchmark 轴；不足以支持“LLM 理解全局 topology”或 Graph-LLM 的 causal structure claim。数值误差、模型选择、walk bias、prompt statistics 和外部 estimator 责任仍混合。

## 局限与潜在捷径

- 作者明确承认：任务没有覆盖所有大图属性；受 API 成本和 token 消耗限制，没有对 sampling size、burn-in、walk initialization 等多个超参数做充分 ablation；实际 graph access 的 seed diversity 可能困难。
- 实验直接暴露：simple random walk 在多个配置明显弱于 MH；real-world 节点/边估计的 mean 与 median 差距大，LLM 偶尔产生数量级错误；community 数量估计偏差约 2 个；Betweenness/Closeness 明显难于 PageRank；BA 与 LFR 的 degree-skew 相似时 structure classification 混淆。
- 研究者推断、尚待验证：random walk 的 stationary/degree bias、局部 seed 覆盖、walk length 与 graph size 的耦合可能让模型利用 degree/coverage proxy，而非全局 topology；匿名节点仍保留 serial-number 形式；多条 prompt 或 diverse seeds 的聚合可能成为主要增益来源；LLM 可能只是把手工设计的统计量映射到熟悉的图类型先验。
- 不足所在模块：random-walk sampler、burn-in/seed protocol、statistics summarizer、prompt template、LLM API variance、classical estimator baseline、synthetic/real-world split 和缺失的 permutation/counterfactual/responsibility protocol。
- 可能的替代解释：degree distribution 直接决定 BA/ER/Grid 识别；PageRank 与 random-walk visit frequency 相关；community repetition 可能只反映局部 mixing；Chapman estimator 已编码核心 graph-size logic；模型规模/推理模式和 API 输出随机性可能比 topology representation 更重要。

## 与当前研究的关系

- 支持或挑战的研究假设：H10 得到补充支持，OOD 评测应增加“partial access + scale”轴，但仍要与 semantic、generator/transitivity、cross-task 和 topology-family 轴分开；H1/H5 得到边界强化，结构统计输入和大图任务成功不等于 LLM causal topology use；H14 的 task-conditional 观点得到侧面支持，因为 EstGraph 选择的是可由 walk statistics 近似的估计任务；H2/H3 仍没有直接新证据。
- 可以复用的实验或方法：将 EstGraph 的 20% sampling、MH vs SRW、不同 walk budget、diverse seeds、degree-only statistics、real-world scale 和 robust median aggregation 迁移为 I1 的 access-aware OOD slice；同时在小图保留 exact relabeling、fixed-text key/irrelevant topology intervention 和 output equality。
- 尚未解决的关键问题：当 GraphTokenizer 或其他 Graph-LLM 只能访问随机 walk/subgraph summary 时，是否仍能保持等价序列化稳定、关键 topology direction accuracy 和 held-out topology-family 泛化；若仅 degree/visit-frequency baseline 已复现增益，是否应否定 LLM 的 topology 归因。

## 可证伪的新想法

- 假设：I1 的 topology-OOD 不应只做 full-graph size extrapolation，还应加入 access-aware slice。若固定节点文本和输出格式，在 MH/SRW、不同 coverage、不同 seeds、同图 relabeling 和 held-out scale/topology family 下，离散可寻址接口仍同时保持 decode/output equality、关键干预方向正确和无关干预稳定，并超过 degree-only/walk-stat-only/readout-only，则可认为接口提供了独立的结构证据；若 degree-only 或 walk-stat summary 复现全部增益，则该接口只提供任务级统计映射。
- Idea 推导链：`GraphTokenizer reversible/BPE 但缺 scale/access OOD -> EstGraph 证明 random-walk summary 可把 LLM 评测扩展到 2.39M-node partial-access graphs，同时暴露 SRW/MH、coverage、seed 和 degree-bias 影响 -> 将 access regime 与 topology family、permutation、fixed-text topology intervention 联合控制 -> 可比较 full serialization、sampled discrete view、Graph-KV mask-only、degree-only 和 readout-only 的责任与泛化`。
- 结合的历史论文：GraphTokenizer（arXiv:2603.11099）、NLGift（doi:10.18653/v1/2024.findings-emnlp.127）、Graph-KV（arXiv:2506.07334）、Lost in Serialization（arXiv:2511.10234）。
- 最接近工作：至少三项独立核验如下。

| 工作 | 已解决 | 尚未解决 | 与 I1 的最小实质差异 | 一手来源 |
|---|---|---|---|---|
| EstGraph | partial-access random-walk statistics、百万级图、四类 global-property estimation 和 classical sampling baseline | 没有 discrete graph tokenizer、node-relabeling equality、fixed-text topology intervention 或组件责任分离 | I1 将其作为 access-aware OOD slice，并要求与等价性、因果方向和 responsibility split 联合通过；不是再做一个大图估计 benchmark | [ACL paper page](https://aclanthology.org/2026.acl-long.1846/)、[official PDF](https://aclanthology.org/2026.acl-long.1846.pdf)、[Zenodo data record](https://zenodo.org/records/19632942) |
| NLGift | semantic/numeric/structural/reasoning/real-world transfer 与 graph-size、generator/transitivity、cross-task 的 generalization audit | 主要是纯文本 LLM、小图 exact tasks；没有 partial-access random-walk、GraphTokenizer interface 或 LLM/GNN/readout responsibility split | I1 增加 access-limited scale/seed/coverage control，并把 transfer 结果绑定到 fixed-text topology direction 与模块责任，而非只报告 PGR/Strong Recovery | [ACL paper page](https://aclanthology.org/2024.findings-emnlp.127/)、[official PDF](https://aclanthology.org/2024.findings-emnlp.127.pdf) |

| Unified Multi-Dimensional Benchmark / GraphGym | 以 graph size、task complexity、task description、graph loading、task source 五维自动构造 202 个任务，并比较 text/code/augmented reasoning | 截至本轮官方 arXiv 页面称 code/data 将发布；没有确认的 random-walk partial-access protocol、discrete tokenizer equality 或 fixed-text causal topology | I1 只借用其多维 OOD 设计原则，增加 sampling access 与 responsibility closure，不把自动 benchmark 生成视为新模型贡献 | [arXiv paper page](https://arxiv.org/abs/2608.12391) |

- Novelty 状态：已初步区分；I1 的 access-aware 扩展主要是新评测协议/数据构造，不是单独新模型。没有发现 EstGraph、NLGift、GraphEval36K 或 GraphGym 已把“离散可寻址接口 + partial-access sampling controls + prediction equality + fixed-text key/irrelevant topology intervention + GNN/LLM/readout split + topology-family OOD”作为同一完整协议。Novelty 仍只记 1/2，不使用“首次”表述。
- 最小实验：第一阶段在 100--1,000 个 synthetic labeled graphs 上构造 semantic-sufficient/structure-essential matched tasks；对 full graph、MH/SRW sampled view、degree-only 和 shuffled-walk statistics 分别执行 `10 relabelings × 4 edge orders × 3 starts/directions`，记录 serialized/BPE equality、decode isomorphism、prediction equality、output KL、key/irrelevant direction accuracy。第二阶段把 graph size 扩展到 1,000/10,000/100,000，改变 coverage、burn-in、seed diversity 与 BA/ER/LFR/Grid held-out family，加入 EstGraph 的 median relative error/PGR 作为 access-aware OOD 指标。
- 对照组：GraphTokenizer Feuler/FCPP+BPE、raw edge list、continuous projector、Graph-KV mask-only、degree-only/walk-stat-only、GRAIN parser/oracle、solver-disabled、GNN-only、LLM-only、readout-only、text-only、random-label/text shuffle，以及 MH/SRW、single/multiple seed、short/long walk。
- 支持条件：structure-essential 子集先对 semantic-only/HN-1/MLP/readout-only 形成独立 topology signal；同图 relabeling 和 edge-order 下 token/hidden/output 稳定；关键拓扑 direction accuracy 高、无关拓扑 stability 高；在 matched token/compute budget 和 scale/access/topology-family holdout 下，完整离散接口超过 degree-only/walk-stat-only、Graph-KV mask-only 与 parser/readout/GNN-only，并且效果不只来自 longer prompt 或 higher coverage。
- 失败或否定条件：MH/SRW 采样统计或 degree-only 复现完整效果；coverage/seed 变化造成大幅输出漂移；relabeling、edge order、start/direction 或 disconnected components 触发 sequence/BPE/output flip；关键 topology 没有方向响应；readout/GNN/parser-oracle 复现全部 direction accuracy；或者只在 standard split、小图或高覆盖率上改善，topology-family/scale/access OOD 失败。
- 资源和实现风险：EstGraph 官方 Zenodo 记录列出 1.3 GB 的 `EstGraph.zip`，不必在首步下载；第一阶段可用 CPU synthetic graphs 和 API-free local baselines，LLM API 会带来费用与输出方差；GraphTokenizer 官方 release 的本轮静态核验发现当前 bundled Python 缺少 `torch`、`dgl`、`networkx`、`rdkit`、`transformers`，因此只完成 source audit，未虚构 runtime equality 结果。完整 sampled Graph-LLM 对照的 GPU/API 成本待依赖环境和样本量确定。

## 可信度与待核验项

- 直接由全文支持的事实：EstGraph 的四类任务、synthetic/real-world graph scale、random-walk/MH sampling、prompt statistics、classical baselines、四个 LLM、主要结果表、Appendix recommendations、未做 sampling hyperparameter ablation 的 limitation，以及官方 Zenodo 数据入口。
- 我的推断：random-walk degree bias、visit-frequency/PageRank 相关性、Chapman estimator 和 hand-crafted prompt 可能承担了大部分结构计算；partial-access/scale OOD 与 topology-family OOD、permutation consistency、causal topology use 是不同轴；I1 应将 sampled access 作为补充条件而不是替代 fixed-text intervention。
- 待核验：EstGraph source/data package 的完整可复现性、每类 task 的 exact seed/coverage distribution、LLM API 多次运行方差、random-walk statistics 在 degree-matched topology pairs 上是否可区分、GraphTokenizer 官方 runtime 的实际 sequence/BPE/decode equality，以及 sampled discrete view 是否能保留 key/irrelevant topology direction。
