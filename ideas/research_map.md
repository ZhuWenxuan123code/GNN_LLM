# 连续研究地图

## 当前阶段

阶段 1：建立代表性方法与结构证据的基线地图，识别现有 Graph-LLM 工作在“结构可辨识、置换一致、因果利用、跨拓扑泛化”四个层次上的证据缺口。

### 2026-08-18 状态更新说明

- H1：维持“部分支持”。HLM-G 是一个结构化 hierarchical encoder 的正面边界案例：它在 node relabeling 下稳定，但没有 topology counterfactual 或 LLM causal-use 证据，因此不能推翻“结构输入/任务增益不等于 LLM 因果使用”。
- H2：维持“部分支持”。HLM-G 的低 permutation drop 说明专用 local/global bottleneck 可以缓解 node-index shortcut；但 BERT、Llama-3、GraphWiz 的对照仍显示普通图文本模型会受 node position 影响，且 HLM-G 尚未迁移到 GNN-LLM/GTokenLLM。
- H5：维持“待验证”，新增正面设计证据。HLM-G 测量了 permutation robustness，却没有测同一模型的 topology counterfactual，进一步说明两类能力必须分开报告，不能由前者推出后者。

### 2026-08-19 状态更新说明

- H1：维持“部分支持”。LLM-GCE 使用 LLM 生成 TP/CTP 并在五个分子数据集上改善 GCE 的 feasible validity/proximity，但最终 counterfactual 是否有效由 GT-GNN 的 prediction loss 和 RDKit feasibility 决定；因此它补充支持“LLM-assisted graph system 的增益不等于 LLM 因果使用拓扑”。
- H6：维持“待验证”，但证据边界更清楚。与 IP-GLLM 的 latent-space soft intervention 不同，LLM-GCE 是 graph-level counterfactual explainer；它证明了可用的 GNN 反事实搜索接口，却没有证明 LLM 是拓扑干预的因果执行者。
- H8：新增并标记“待验证”。LLM-GCE 的 direct-LLM 失败、`q_G ⊕ z_G` 拼接和 GT-GNN feedback 提示语义生成、GNN oracle 与 graph decoder 的责任必须分离评估。

### 2026-08-23 状态更新说明

- H1：维持“部分支持”。NLGift 在纯文本 LLM 上显示 semantic/numeric 的有限迁移不能外推到 cross-task、graph-size 或 synthetic-to-real transfer；这补充了“任务增益和表面泛化不等于因果结构使用”的边界证据。
- H2：维持“部分支持”。NLGift 的 graph size shift 明显比 generator/transitivity shift 更难，但它没有 node relabeling 或 isomorphic consistency，因此不能把 size/generalization gap 直接解释为 node-index shortcut。
- H5/H6：维持“待验证”。NLGift 提供可复用的 PGR、size/generator/transitivity 与 cross-task 轴，但没有 fixed-text topology intervention 或 GNN/LLM responsibility split。
- H10：新增并标记“待验证”，把 topology OOD 拆为 semantic、size、generator/transitivity、cross-task 和 real-world 五条互不等价的迁移轴。
